# ejjjminer — открытый майнер Pearl (PRL) для NVIDIA под HiveOS

Майнер алгоритма **pearlhash** (Proof-of-Useful-Work сети Pearl) для видеокарт NVIDIA.
**Без комиссии разработчика и без телеметрии.** Майнер открывает ровно одно сетевое соединение —
к пулу, который вы указали. Есть ещё локальный API статистики на `127.0.0.1` (нужен для HiveOS).

Протокол написан с нуля по исходникам официального репозитория
[pearl-research-labs/pearl](https://github.com/pearl-research-labs/pearl) (zk-pow, pearl-blake3,
miner-base). Чужие бинарники (SRBMiner, rgminer) не использовались и не модифицировались.

## Как это работает

Каждая попытка выглядит так:

1. Майнер берёт матрицы `A` (m×k) и `Bᵀ` (n×k) с int8-значениями. В первый чанк `A` вписан 64-битный nonce.
2. Строятся Merkle-деревья BLAKE3, ключ — `job_key = BLAKE3(header ‖ config)`. Из них получаются сиды шума.
   Для высоты ≥ 99000 они «солятся» (сертификат v3).
3. На GPU генерируется низкоранговый шум (ранг 128) и прибавляется к матрицам. Затем идёт int8-GEMM на
   тензорных ядрах (`mma.sync.m16n8k32`). Каждые 128 шагов по k частичные суммы каждого hash-тайла 2×64
   сворачиваются XOR'ом в 16-словный транскрипт.
4. Для каждого тайла считается `BLAKE3(транскрипт, key = a_seed)`. Если значение ≤ `target × (h·w·k)`,
   тайл становится шарой.
5. Для шары строится `PlainProof`: строки A, столбцы B и Merkle-мультидоказательство, сериализация bincode.
6. Перед отправкой шара **проверяется независимым CPU-верификатором** (порт `verify_plain_proof`).
   Невалидная шара на пул не уходит.

Hash-тайл берётся из официального майнера: rows `[0,8]`, cols `{0,1,8,9,…,248,249}`. Он ложится ровно
на раскладку аккумуляторов mma: каждый поток держит свой тайл целиком в регистрах.

Хешрейт выводится в H/s, где 1 H = одно int8-умножение-сложение. Это та же «работа», по которой пул
считает сложность: в среднем на одну шару приходится `diff · 2³²` H.

## Требования

- Видеокарта NVIDIA:
  - RTX 30xx / 40xx / 50xx (compute 8.0+) — кернел на тензорных ядрах;
  - GTX 10xx / 16xx, RTX 20xx — запасной кернел на `dp4a`, медленнее.
- Драйвер NVIDIA с поддержкой CUDA 11.0+ (≥ 450). CUDA Toolkit не нужен: PTX компилирует драйвер.
- Linux x86-64, glibc ≥ 2.17. Подходит любой HiveOS.

## Установка в HiveOS

1. Положите `ejjjminer-1.0.9.tar.gz` туда, откуда риг сможет скачать его по HTTP(S):
   GitHub Releases, свой веб-сервер и т. п.
2. Создайте полётный лист (Flight Sheet):
   - **Coin**: PRL (или любая, если такой нет);
   - **Wallet**: ваш `prl1…` адрес;
   - **Pool**: *Configure in miner*;
   - **Miner**: *Custom*. Нажмите **Setup Miner Config** и заполните:

| Поле | Значение |
|---|---|
| Miner name | `ejjjminer` |
| Installation URL | `https://github.com/dzhelybaev/prlminer/raw/main/dist/ejjjminer-1.0.9.tar.gz` |
| Hash algorithm | `pearlhash` |
| Wallet and worker template | `%WAL%.%WORKER_NAME%` |
| Pool URL | например `pearl-eu2.luckypool.io:3360` (несколько адресов через пробел = резерв) |
| Pass | `x` (или `d=…`, если пул поддерживает фиксированную сложность) |
| Extra config arguments | по желанию: `--devices 0,1`, `--kernel auto`, … |

Можно поставить и вручную: распакуйте архив в `/hive/miners/custom/` (получится
`/hive/miners/custom/ejjjminer/`), а в полётном листе укажите тот же Miner name.

Для запуска вне HiveOS:

```
./ejjjminer -o pearl-eu2.luckypool.io:3360 -u prl1ВАШ_АДРЕС.rig1
```

### Совместимость с пулами

Поддержан «объектный» stratum-диалект Pearl — его используют Suprnova, LuckyPool, HeroMiners, Kryptex
и другие. Не поддержаны:

- TLS-порты — указывайте обычный TCP-порт пула;
- пулы с позиционным диалектом и challenge-авторизацией (alphapool).

Если пул отклоняет все шары кодом 23/26, майнер сам напишет в лог, что попробовать: `--cert 2|3`
или `--share-target raw`.

## Первый запуск — обязательно

```
./ejjjminer --list-devices
./ejjjminer --selftest            # GPU-кернелы сверяются с CPU-эталоном бит в бит
./ejjjminer --benchmark 60        # синтетическая работа, все шары проверяются локально
```

Самотест выполняется и при каждом обычном старте. Если кернел на тензорных ядрах не прошёл проверку,
майнер переключится на `dp4a`. Если и он не прошёл — карта будет отключена: майнить с неверным
кернелом бессмысленно. Первый старт может занять до минуты, пока драйвер компилирует PTX.
Результат кешируется в `~/.nv/ComputeCache`.

## Параметры

```
-o, --pool URL        пул (повторить для резервных)
-u, --user LOGIN      адрес[.воркер]
-w, --worker NAME     имя воркера
-p, --pass PASS       пароль пула (x, d=…)
-d, --devices LIST    индексы CUDA-устройств, напр. 0,2
    --kernel K        auto | mma | dp4a
    --fused M         auto | on | off — шум генерируется прямо в GEMM-ядре (auto: замер при старте)
    --variant V       принудительно выбрать ядро: fmma | v2a | v2b | v2c (по умолчанию самое быстрое по замеру)
    --rows N          строк матрицы на попытку (по умолчанию 128 × число SM)
    --tile W          32 (официальный тайл 2×64, по умолчанию) | 16 | 8
    --cert C          auto | 2 | 3 — версия деривации сидов (auto: v3 с высоты 99000)
    --share-target T  scaled (по умолчанию) | raw
    --api-port P      порт API статистики (4068), 0 — выключить
    --benchmark SEC   бенчмарк без пула
    --log FILE        дублировать лог в файл
```

API: `curl http://127.0.0.1:4068/` возвращает JSON с хешрейтом, шарами и данными по картам.
`h-stats.sh` передаёт хешрейт в HiveOS в kH/s: в H/s числа слишком большие, HiveOS их обрезает.

## Как проверялась корректность

В среде разработки не было GPU, поэтому проверка многоуровневая
(`tests/run_all.sh`, `PEARL_REPO=… tests/run_all.sh`):

| Что | Чем проверено |
|---|---|
| BLAKE3, Merkle-дерево (= корень BLAKE3) | официальные тест-векторы BLAKE3, длины до 100 чанков |
| Сиды (v2 и v3) | закреплённые значения из `zk-pow/src/api/seed.rs` |
| Генерация шума, транскрипт, хеш джекпота | **официальный Python-код Pearl** (`noise_generation.py`, `noisy_gemm.py`), запущенный без изменений |
| CUDA-кернелы | исполнение реального исходника в SIMT-эмуляторе (потоки, барьеры, модель фрагментов `mma.sync` по PTX ISA) и сравнение каждого тайла с CPU |
| Хост-часть GPU (загрузка, буферы, double-buffering) | эмулированный `libcuda.so` + мок-пул |
| PlainProof | независимый верификатор на Python (`tests/pyverify.py`) в мок-пуле принимает шары, построенные C-кодом |

**Чего проверить было нельзя:** реальное железо (на риге это делает самотест) и реальные пулы.
Скорость станет известна только на ваших картах.

## Сборка из исходников

Нужны `gcc`, `clang` (≥ 15, с бэкендом NVPTX) и `python3`. CUDA Toolkit не требуется.

```
make portable        # build/ejjjminer-portable (glibc ≥ 2.17)
tests/run_all.sh     # все тесты, GPU не нужен
make package         # build/ejjjminer-1.0.9.tar.gz для HiveOS
```
